2. Purpose and Acceptance Standard

This document defines the acceptance checklist for the first working IAM-Distribution V1.0 build. IAM is accepted only if it can surface priorities correctly, apply workflow discipline correctly, protect visibility and restricted notes, preserve archive/history rules, and pass the active UAT workbook and sample scenario expectations.

Acceptance means the build behaves according to the approved IAM rules, not merely that screens exist.

A working UI is not enough if the ranking, workflow, visibility, or archive logic is wrong.

Controlled validation readiness requires that major blockers are resolved and known limitations are documented honestly.

3. Locked Hard Rules

IAM is the inventory action engine. It does not replace RSE, IFM, or the broader Decision OS framework.

IAM V1 is a validation-stage build, not a final enterprise version.

One company per workspace/environment in V1.

Priority weights are fixed in V1.

Cash impact leads by default; service/operational risk can override only when clearly more dangerous.

New priorities and holdovers rank separately.

Top 2 remain the core weekly surfaced priorities.

Rejected top priorities do not auto-replace with lower-ranked items in the same cycle and the week may end with zero approved top priorities.

Management may elevate additional items, and materially important out-of-cycle events may create a 3rd top priority.

Management-priority items can remain active outside the normal top-2 cycle.

Grouped actions require one business decision case, one owner, and one action type.

Grouped actions are handled inside Action Detail View in V1.

Completed and archived actions never reopen; similar later issues become new actions with new IDs.

Management-only notes are protected and restricted content must not appear in ordinary non-management views or ordinary exports.

Build should not stall waiting for perfect Keystroke / AIMS mapping. Final source mapping remains a separate addendum.

Any file intended for Keystroke upload or re-import must be tab-delimited and end in .txt.

CSV/XLSX may be used for review, mapping, QA, internal analysis, or customer review, but not as Keystroke import-ready files.

6. Critical Blockers

Top-2 featured model fails materially.

Rejected top priorities auto-replace with lower-ranked items in the same cycle.

Holdovers are not separated from new priorities.

Grouped actions allow multiple owners or multiple action types in one grouped action.

Management-only protected notes leak into ordinary non-management views.

Protected content leaks into ordinary exports.

Completed or archived items can reopen in V1.

Low-confidence issues are presented as strong certainty or false precision.

Material management-priority item behavior fails or disappears improperly.

Material-event 3rd-priority behavior breaks the approved top-2 model.

10. Playbook-Library Acceptance Additions

The Inventory Cash Recovery Action Playbook Library must be included in the active IAM handoff set.

IAM must be able to reference or use the playbook library for trapped-cash/excess inventory actions.

Controlled Runoff must exist as a distinct accepted playbook path, not merely an implied stop-buy action.

Follow-Up Measurement must exist as a distinct accepted playbook path after material recovery actions.

Acceptance review should confirm that playbook recommendations or references do not violate IAM boundary rules.
