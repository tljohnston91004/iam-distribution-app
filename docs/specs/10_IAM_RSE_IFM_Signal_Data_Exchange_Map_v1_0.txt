Document 10 - IAM-RSE-IFM Signal / Data Exchange Map

Cross-module integration addendum for IAM development in Cursor

Status: Active working cross-module integration addendum for IAM Cursor/development handoff

1. Purpose

This document defines how IAM, RSE, and IFM should communicate while remaining separate modules. It is meant to guide Cursor/development so IAM can consume root-cause and funding signals without taking over RSE or IFM calculation authority.

2. Module Roles

RSE

Owns replenishment settings logic

Owns Min/Max review

Owns classification logic

Owns replenishment-root-cause correction

IFM

Owns inventory funding capacity

Owns inventory capital discipline

Owns cash-pressure / funding-urgency context

IAM

Owns action selection

Owns action tracking and owner assignment

Owns due/review timing, holdovers, completion/archive, and follow-up measurement

Owns trapped-cash recovery playbooks

3. Communication Principle

RSE informs IAM about root cause and replenishment-pressure signals.

IFM informs IAM about economic urgency and patience tolerance.

IAM sends action status and outcome feedback back to RSE and IFM.

Each module keeps its own calculation authority; signals should support decisions, not silently rewrite another module’s logic.

4. Signal Types

Informational: useful context only

Advisory: strong recommendation / decision-support input

Workflow-Relevant: affects IAM routing, follow-up, or escalation

Outcome / Feedback: closes the loop after action is taken

9. Recommended IAM Decision Use of Incoming Signals

From RSE

Identify root-cause replenishment issues

Trigger Replenishment Setting Correction through RSE

Decide whether Stop Replenishment alone is enough

Decide whether Controlled Runoff is credible

Check whether recurrence risk should fall after correction

From IFM

Decide how much patience is acceptable

Judge whether Controlled Runoff is still appropriate

Decide whether to escalate to markdown, liquidation, write-off, or stronger management review

10. Recommended Signal Priority Inside IAM

1. IAM’s own issue evidence

2. RSE root-cause / replenishment-pressure signals

3. IFM cash-pressure / funding-urgency signals

IAM should remain the action engine. RSE and IFM should influence IAM, not replace IAM’s purpose.

11. Controlled Runoff Rule with RSE + IFM

Prefer Normal Sell-Through / Controlled Runoff when demand is still credible, margin preservation matters, RSE correction is in place or underway, IFM does not indicate intolerable cash pressure, and item risk is manageable.

Escalate to stronger recovery when RSE correction is absent or failing, IFM indicates high cash pressure / low patience tolerance, demand is too weak, runoff window is too long, or item risk is rising.

12. Recommended Technical Design Rule

Exchange signals as flags, status fields, advisory indicators, timestamps, and module-reference IDs.

Do not use uncontrolled direct edits, opaque overrides, or one module silently rewriting another module’s decision layer.

15. Package Placement Recommendation

Use this as a standalone cross-module integration addendum.

Also include it in the IAM Cursor package so Cursor sees IAM’s intended relationship with RSE and IFM during IAM development loading.

16. Recommendation

Best structure: RSE informs root cause, IFM informs economic urgency, and IAM manages action and feedback. Treat this as the cross-module integration rule: connected modules, separate decision authority.
