1. Purpose

This document is the package index and build checklist for Inventory Action Manager - Distribution V1.0. It defines what the IAM package contains, how it should be loaded into Cursor, what the V1 build must include, and which rules cannot be violated.

3. Locked Hard Rules

IAM is the inventory action engine. It does not replace RSE, IFM, or the broader Decision OS framework.

IAM V1 is a validation-stage build, not a final enterprise version.

One company per workspace/environment in V1.

Priority weights are fixed in V1.

Cash impact leads by default; service/operational risk can override only when clearly more dangerous.

New priorities and holdovers rank separately.

Top 2 remain the core weekly surfaced priorities.

Rejected top priorities do not auto-replace with lower-ranked items in the same cycle and the week may end with zero approved top priorities.

Management may elevate additional items, and materially important out-of-cycle events may create a 3rd top priority.

Management-priority items can remain active outside the normal top-2 cycle.

Grouped actions require one business decision case, one owner, and one action type.

Grouped actions are handled inside Action Detail View in V1.

Completed and archived actions never reopen; similar later issues become new actions with new IDs.

Management-only notes are protected and restricted content must not appear in ordinary non-management views or ordinary exports.

Build should not stall waiting for perfect Keystroke / AIMS mapping. Final source mapping remains a separate addendum.

Any file intended for Keystroke upload or re-import must be tab-delimited and end in .txt.

CSV/XLSX may be used for review, mapping, QA, internal analysis, or customer review, but not as Keystroke import-ready files.

4. Product Summary

IAM-Distribution helps a distribution business decide what inventory action matters most now, which issues should be surfaced first, who should own them, how they should move through approval, assignment, holdover, completion, and archive, and how management should keep current work and completed history clearly separated.

IAM is not a replenishment settings engine, a purchasing execution system, or a general dashboard without action discipline.

12. Inventory Cash Recovery Playbook Library Integration

Add Document 9 - IAM Inventory Cash Recovery Action Playbook Library to the active IAM package set.

Treat the playbook library as the formal action-library reference for trapped-cash / excess / weak-moving inventory cases.

Use the library together with the active build brief and UAT workbook.

Required package-control implications

Package references should show that IAM now includes a formal playbook group for inventory cash recovery actions.

Cursor should treat the playbook library as a referenced action-framework document, not as a replacement for core logic files.

Pre-handoff checklist should include confirmation that the playbook library is included and referenced in the relevant IAM package files.
