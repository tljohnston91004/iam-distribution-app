2. Purpose and Output Principle

This document defines IAM management outputs, internal reviewer outputs, operational exports, archive/history outputs, output validation, visibility controls, and file/output versioning.

An output is a screen summary, report, table, or view produced by IAM.

An export is a downloadable file created from an IAM output or controlled data set.

IAM outputs must reflect workflow state, confidence, visibility, and archive rules rather than simply dumping raw data.

Management-facing outputs should be plain-English and action-oriented.

Internal reviewer outputs may contain deeper confidence, visibility, lineage, and protected-note detail where role-appropriate.

3. Locked Hard Rules

IAM is the inventory action engine. It does not replace RSE, IFM, or the broader Decision OS framework.

IAM V1 is a validation-stage build, not a final enterprise version.

One company per workspace/environment in V1.

Priority weights are fixed in V1.

Cash impact leads by default; service/operational risk can override only when clearly more dangerous.

New priorities and holdovers rank separately.

Top 2 remain the core weekly surfaced priorities.

Rejected top priorities do not auto-replace with lower-ranked items in the same cycle and the week may end with zero approved top priorities.

Management may elevate additional items, and materially important out-of-cycle events may create a 3rd top priority.

Management-priority items can remain active outside the normal top-2 cycle.

Grouped actions require one business decision case, one owner, and one action type.

Grouped actions are handled inside Action Detail View in V1.

Completed and archived actions never reopen; similar later issues become new actions with new IDs.

Management-only notes are protected and restricted content must not appear in ordinary non-management views or ordinary exports.

Build should not stall waiting for perfect Keystroke / AIMS mapping. Final source mapping remains a separate addendum.

Any file intended for Keystroke upload or re-import must be tab-delimited and end in .txt.

CSV/XLSX may be used for review, mapping, QA, internal analysis, or customer review, but not as Keystroke import-ready files.

8. Internal Reviewer Output

Internal reviewer output should still remain usable and not become an uncontrolled diagnostic dump in V1.

12. Archive / History Output Rules

Archive/history output should act as useful history rather than a dead status bucket.

Completed items may remain visible briefly before archive according to approved workflow behavior.

Archive/history output should preserve action ID, title/label, action type, owner, first surfaced date, completed date, archived date, and original estimated impact where supportable.

Actual achieved impact should appear only when easily supportable.

Archived items never reopen in V1; later similar issues become new actions with new IDs.

16. Playbook Output and Export Reference

Management-facing output should be able to show the selected or recommended cash-recovery playbook in plain-English action language where relevant.

Action tracker outputs and exports should be able to show playbook name, owner, due/review date, current status, and follow-up measurement requirement.

Internal reviewer outputs may show deeper playbook-selection reasoning where role-appropriate.

Ordinary exports must still respect protected-note and visibility rules even when playbook detail is included.

Archive/history output may preserve the playbook used on the action as part of useful history where supportable.
